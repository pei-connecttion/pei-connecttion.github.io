      # Goal
      **An information system to optimize processes in associations**
      The project aims to provide a zero-cost, modular ERP solution tailored for associations to manage inventory, finances, and memberships efficiently[cite: 3, 34].

      ## State of the Art Analysis
      ![State of the Art Comparison](/images/milestones/m3/sota.png)

      **Cost Efficiency**: connecTTion is free (0€), whereas competitors like SAP (55€), Dynamics 365 (53€), and NetSuite (125€) have high monthly costs[cite: 30, 31, 32, 34].
      **Feature Coverage**: The system covers Inventory, Modularity, Integrated CRM, Membership Management, and Low Budget constraints[cite: 36, 37, 38, 40, 42].
      **Differentiation**: Unlike SAP, Dynamics, NetSuite, and Sage, connecTTion specifically includes Membership Management and is designed for a low budget[cite: 30, 33, 40, 42].

      ## Actors
      **Board, Sections, and Members**
      The system serves three primary actors: the Board, the Sections (departments), and the Members[cite: 54, 56, 59].
      During the development phase, the team identified at least 35 use cases[cite: 55].
      For this milestone (M3), the team demonstrated 6 key use cases that distinguish the platform from competitors[cite: 60].

      ## Requirements
      **Functional Requirements**
      The system must allow the board to create new roles[cite: 67].
      The system must allow the board to view reports and stats about the total number of members, roles, and quota payment status[cite: 68, 70, 72].
      The system must allow authorized users to view detailed information about all expenses of the association[cite: 74, 76].
      The system must allow users to print product labels[cite: 78].
      The system must allow users to enter additional product details such as description[cite: 79].

      **Non-Functional Requirements**
      The system should use RBAC (Role-based access control) to manage user roles and enforce permissions[cite: 89].
      The system should have 90% uptime, resulting in a maximum of 36.5 days of downtime per year[cite: 91].

      ## System Architecture
      ![Component-Level Architecture](/images/milestones/m3/architecture_components.png)
      ![Deployment Architecture](/images/milestones/m3/architecture_deployment.png)

      **Core Structure**: The ERP Application consists of a "Core" containing Role-based Access Control, Dashboard and Analytics, Membership Manager, and a Plugin Manager[cite: 125, 126, 129, 130].
      **Modular Plugins**: The system is extended via plugins including Inventory, Financial, CRM, Report, Logging, Notifications, and Update Members modules[cite: 119, 121, 123, 127, 128, 131, 132].
      **Tech Stack**: The architecture employs Nginx as a Reverse Proxy, Python/Django for backend services, React for the User Interface, and PostgreSQL for the database, all hosted on Hetzner[cite: 154, 157, 162, 195, 197].

      ## Demo Scenarios & Use Cases
      ![Demo Overview](/images/milestones/m3/demo_overview.png)

      For Milestone 3, the team demonstrated the following flows:

      **1. User Management**
      **Goal**: Create members and groups, and assign a group to each member[cite: 225].
      **Architecture Flow**: `POST /api/auth/groups/` is sent through the reverse proxy to the Authentication and Core modules to store group data[cite: 260, 509].

      **2. Import Association Members**
      **Goal**: Import members using a CSV file to add multiple members efficiently with minimal manual effort[cite: 323, 324].
      **Visualization**: A table view allows admins to see active status, assigned groups (e.g., Board, GLUA, NERD), and quota status[cite: 345].

      **3. Import Financial Data**
      **Goal**: Import financial data from a CSV file and assign expenses to specific sections[cite: 351].
      **Architecture Flow**: `POST /api/financial/transactions/import-csv` handles the data ingestion[cite: 406].

      **4. Section Financial Dashboard**
      **Goal**: Create a Section and assign permissions so only associated users can access its specific Financial Dashboard[cite: 426, 427].
      **Features**: View current balance, total income/expenses, and filter transactions by date or entity[cite: 372, 388, 389, 450].

      **5. Inventory Management**
      **Goal**: Create inventory categories (e.g., Technology & IT) and subcategories (e.g., Computers, Monitors), and add items[cite: 554, 567, 577].
      **Architecture Flow**: `POST /api/inventory/items/` and `POST /api/inventory/categories/` manage the data persistence[cite: 592, 595].

      **6. QR Code Generation**
      **Goal**: Generate and print QR codes for inventory items to allow quick identification and tracking[cite: 610, 611].
